Same root surface family as v13.6.1 sparse-feed findings: Daily Statement assumes a modest, dense, fully-named account universe and degrades quietly when a real feed violates that.

**Three omission mechanisms (audit §Root cause + Legs A/B):**
1. **NULL-display drop (both renderers).** `account_name || ' (' || account_id || ')'` is NULL whenever `account_name` is NULL (SQL NULL-propagation, all three dialects). App2 fetcher `WHERE account_display IS NOT NULL` drops it; QS LinkedValues equivalent. Disproportionately hits the singleton control accounts (low-cardinality, transaction-light → only reachable through the picker). Dashboard-wide: all 7 wide L1 account pickers + Daily Statement + Investigation Anchor.
2. **Hard `LIMIT 2000` cap with client-only typeahead (App2).** `_OPTIONS_CAP = 2000` in `common/html/_tree_fetcher.py::make_options_fetcher` truncates silently; Tom Select filters client-side only so tail is *unreachable*. Clearest victim is the Transfer picker (`transfer_id` always exceeds 2000) + Investigation Chain root transfer.
3. **QS-400 on parameterized `DS_L1_DS_ACCOUNTS` (Daily Statement only).** `GetUniqueAttributeValuesSyncForAnalysis` 400s on parameterized datasets per `docs/reference/quicksight-quirks.md` — the `pL1DsRole` cascade is the only remaining parameterized LinkedValues source (others de-parameterized in BR.x). Server-side search broken outright on QS for this control.

**Ranked fixes (post 2026-06-08 operator redirect):**
- (1) NULL-safe display labels dashboard-wide — `COALESCE(account_name, account_id) || ' (' || account_id || ')'` at the shared `*_display` sites. One convention change fixes the unnamed-account omission across all account pickers on both renderers. **Shipped CQ.1.**
- (2) **Server-side typeahead is the ONLY acceptable answer for unbounded pickers — not a follow-on.** Operator direction (2026-06-08): *"truncating at 2000 rows SUCKS in production. That is NOT the right approach and we shouldn't even have it as a fallback. We must do server side querying."* Drop `_OPTIONS_CAP = 2000` entirely. App2 wires Tom Select's `load` callback to a `?q=<typed>` search endpoint that runs `<col> ILIKE '%<q>%'` against the source dataset and swaps the option set; initial load returns a small seed page (~50 alphabetical) so the picker isn't blank on open. QS native server-side typeahead already does this when the source is unparameterized — which CQ.4 ensures for Daily Statement. The "loud truncation affordance" pre-2026-06-08 approach was a band-aid and is explicitly rejected.
- (3) Daily Statement redesign — drop Role cascade (de-parameterizes the source, restoring QS native server-side typeahead) + add control-account reference list (small text box or compact table pinned at sheet bottom listing singleton/control account `account_display` strings). Operator-recommended concrete redesign; pairs with (2) since it removes the QS-400 blocker.
- (4) StaticValues build-time ceiling guard at 32 — matches `_DATASET_PARAM_STATIC_VALUES_CAP` already in `common/models.py`. Forces any larger universe onto LinkedValues + server-side typeahead at the wiring line, not 10 min into a deploy.

**Sequencing:** (1) shipped. (2) is the foundation everything else builds on; design spike first (CQ.2.a), then implementation. (3) Daily Statement redesign next (operator-recommended; benefits from (2) for QS parity). (4) ceiling guards last (build-time gate, no runtime cost).
